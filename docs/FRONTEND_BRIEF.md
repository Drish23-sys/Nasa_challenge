# Frontend / UX brief

A working reference UI is in `frontend/` (plain JS + Leaflet + Chart.js). Use it as-is, restyle it, or port it to React.
Whatever you do, keep these three things: `data/sites.json` as the data source, `scoring.js` for the maths, and the API for AI explanations.

## The one-sentence product
Pick a Moon/Mars site, instantly see which Earth places rehearse it best, and understand *why* (and where they fall short).

## Judge journey (must work in 3 clicks)
1. Open app -> a target is already selected, ranked list + map are visible (0 clicks to a result).
2. Click a site in the list or on the map -> detail panel: score, radar chart, factor bars, "where it breaks down".
3. Click **Explain this match (AI)** -> plain-language explanation.

## Screens / regions
| Region | Contents |
|---|---|
| Left | Target cards (Moon/Mars badge), factor weight sliders, environment-type chips, ranked list with score badges and compare checkboxes |
| Center | World map, markers colored by score (green >= 80, amber >= 65, red below), selected marker highlighted |
| Right | Site detail: title, big score, feature chips, photo (optional), why-it's-an-analog, radar (target vs site), factor bars with "est." badges, break-down callout, AI explanation |
| Bottom drawer | Side-by-side comparison of two ticked sites |

## UX priorities (in order)
1. **Explainability everywhere**: never show a score without the factor breakdown one click away.
2. **Honesty badges**: show "est." where `confidence[factor] === "estimated"`, and the "Placeholder data" banner while `meta.version` contains mock/placeholder.
3. **Always show limits**: the "Where the analogy breaks down" callout is not optional. Judges look for it (it is in the challenge text).
4. **Fast**: scoring is client-side. Do not wait on the API for anything except the AI explanation.
5. **Mobile**: stack map first, then results, then detail (the reference CSS does this under 1050 px).

## Ideas that would impress (pick 1-2, don't do all)
- **Target mini-map** with real Moon/Mars imagery (NASA Trek). Start with these tile templates and test them in the browser:
  - Moon: `https://trek.nasa.gov/tiles/Moon/EQ/LRO_WAC_Mosaic_Global_303ppd_v02/1.0.0/default/default028mm/{z}/{y}/{x}.jpg`
  - Mars: `https://trek.nasa.gov/tiles/Mars/EQ/Mars_Viking_MDIM21_ClrMosaic_global_232m/1.0.0/default/default028mm/{z}/{y}/{x}.jpg`
  - These use a geographic (equirectangular) layout, so use Leaflet with `crs: L.CRS.EPSG4326`, and expect to adjust the zoom offset. The lunar south pole is badly distorted in this projection (Shackleton is at -89.9 deg), so a polar view needs proj4leaflet. **These URLs are untested** - if tiles don't load, fall back to a static NASA image with credit.
- **Site photos**: fill `image_url` and `image_credit` per candidate in `data/sites.json` using Wikimedia Commons or NASA Earth Observatory images (credit required, check each license). The detail panel already renders them if present.
- A **"surprise me"** button that picks a well-known=false site with a high score (the data has a `well_known` flag - this supports the "look beyond famous sites" line of the challenge).
- Animated score bars and a gentle map fly-to when a site is selected.

## Visual direction
Dark "mission control" theme (already in `style.css`: CSS variables at the top). Accent = amber, Moon = grey, Mars = rust.
Keep text high-contrast, never use color alone for meaning (scores always show the number).

## Data contract (don't break this without telling the backend)
```jsonc
{
  "meta": {"version": "...", "factors": {"slope": {"label": "...", "desc": "..."}, ...}, "assumption": "..."},
  "targets":    [{"id","name","body":"Moon|Mars","lat","lon","blurb","factors":{5 values 0-1},"confidence":{...}}],
  "candidates": [{"id","name","type","lat","lon","factors":{...},"confidence":{...},"features":[],
                  "well_known":bool,"why":"...","breaks_down":"...","image_url":null,"image_credit":null}]
}
```
Factor keys: `slope, roughness, temp_range, aridity, basaltic`. The file is regenerated by `backend/pipeline/build_sites.py`; the UI should render whatever is there.

## API (only needed for the AI explanation)
`POST {API_BASE}/api/explain` with `{"target_id","candidate_id","weights":{factor: number}}`
-> `{"explanation": "...", "source": "ai" | "template", "model": "..." | null}`.
Handle: loading state (cold start on free hosting can take 30-60 s), error state (show a friendly message, keep everything else working), and label AI text as AI-generated.

## Deploy settings
- Vercel: Root Directory `frontend`, no build command. Set `API_BASE` in `frontend/config.js` to the Render URL.
- Or skip Vercel: the Render service already serves `frontend/` at its root URL.
